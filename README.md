# AI Post — 排程發文 demo

寫好文字 + 從 `media/` 挑圖 + 設一個時間 → 時間到自動發到 **Facebook 粉絲專頁**（瀏覽器）
跟 **LINE 群組記事本**（桌面）。本機跑，有個單頁 UI。

---

## 1. 先講清楚：LINE 為什麼只能走桌面

你原本的直覺是「大概只能用瀏覽器」。**FB 粉專對，LINE 不對**，而且不是「比較難」——
那個功能根本不在瀏覽器介面上：

| 路線 | 能不能寫群組記事本 | 原因 |
|---|---|---|
| 網頁版 LINE（Chrome 擴充） | ❌ | **從來就沒有記事本功能**。只能文字聊天、貼圖、圖片、檔案。而且本身正在除役（原訂 2025-09-22，被台灣用戶擋下延到 2026 上半年）。 |
| LINE Messaging API | ❌ | 只能 push / broadcast 訊息給官方帳號的好友或它加入的群組。**付費也寫不了記事本**。不是錢的問題。 |
| Android 模擬器 | ⚠️ | 功能有，但 LINE 一個帳號 = 1 手機 + 1 PC。模擬器算一支手機，**會把你真實手機踢掉**。 |
| 第二個 Windows（VM / RDP） | ⚠️ | 同理，會把你現在這台 LINE PC 踢掉。 |
| **這台已登入的 LINE 桌面版** | ✅ | 唯一不用動帳號綁定的路。本專案走這條。 |

FB 那邊相反：**個人檔案**自 2018 年移除 `publish_actions` 後就沒有 API，Groups API 也關了，
所以瀏覽器是唯一路；**粉絲專頁**其實有免費的 Graph API，貴的是申請摩擦（建 Meta App、
`pages_manage_posts`、token 續期）。你選了瀏覽器，這裡就是瀏覽器。

## 2. LINE 要怎麼在不搶你滑鼠鍵盤的情況下操作

這台的 LINE 是 **Qt 6 / QML**（`Qt6Quick.dll`、`Qt6QuickControls2*.dll`；Microsoft Store 那個
`LINE 9.12.1.0` 只是註冊同一顆 exe 的空殼 MSIX）。三件事全部在真的 LINE 上量過，不是推測：

| 問題 | 實測結果 |
|---|---|
| 有沒有 UIA 元件樹可以用名字定位？ | ❌ 走訪 79 個元素，**0 個有名字**（只有 Qt 內部的 `qt_scrollarea_viewport`、`qt_splithandle_`）。QML 的無障礙是逐元素 opt-in，LINE 沒有 opt-in。 |
| 是不是 Electron，可以用 CDP？ | ❌ 不是。 |
| `PrintWindow(PW_RENDERFULLCONTENT)` 抓得到被遮住的視窗嗎？ | ✅ 100% 真實像素。**所以座標是視窗相對的，LINE 擺哪、被誰蓋住都無所謂。** |
| Qt 吃不吃 `PostMessage` 的滑鼠訊息？ | ✅ 在**背景、非作用中視窗**點「群組」分頁 → 22,388 px 改變（靜置雜訊基準 0），**實體游標沒動**。 |
| `WM_CHAR` 能不能打中文？ | ✅ `測試中文ABC123` 原封不動進到搜尋框。**不用剪貼簿、不搶焦點。** |

所以：`PrintWindow` 看 → 模板比對定位 → `PostMessage` 點擊/打字 → 再 `PrintWindow` 當證據。
細節在 `linewin.py`。

**唯一硬限制：LINE 視窗不能最小化**（最小化時它在 `(-32000,-32000)`、尺寸 `160x28`，
`PrintWindow` 只會回一條沒用的舊圖）。**被其他視窗蓋住完全沒關係。**
另外上傳圖片時 Windows 檔案選擇視窗會跳到前面約一秒——這是整支程式唯一會碰你前景的時刻。

## 3. 核心不變量：沒有證據就不算成功

這是整個專案存在的理由，全部實作在 `gate.py` 的 `settle()`，一個函式，三個分支：

| 有證據 | 開火階段 | 結果 |
|---|---|---|
| 有 | 任何 | `success` —— 我們把貼文從畫面上讀回來了 |
| 沒有 | `unknown`（發布鍵按下去了） | `uncertain` —— **可能已經發出去，自己去看一眼。系統不會自動重試。** |
| 沒有 | `not_fired`（還沒按） | `failed` —— **可以證明沒發出去，修好再跑一次是安全的** |

兩條規則：

1. **沒有回讀證據，永遠不算成功。** 「那行 click 沒有丟例外」不是證據。
   FB 的證據是「發文後，目的地多了一個發文前沒有的東西」—— 一個新的貼文 id，或一段新的文字。
   LINE 的證據是指定的模板圖出現在畫面上。拿不到 → `uncertain`，不是 `success`。
2. **只有「能證明沒開火」才可以重試。** 頻道在**按下發布的前一行**呼叫 `attempt.firing()`。
   在那之前出任何事 = `failed`（可安全重跑）；之後出任何事 = `uncertain`（人去看）。

`uncertain` 是**一等公民的終局狀態**，不是一種失敗。它是「我按了，然後線斷了」這件事的誠實答案，
也是唯一會叫你親自去確認的狀態。重複發文對你是真實傷害，所以寧可留著不確定，也不自動重試。

## 4. 環境設置

### 你需要先有的東西

| | 說明 |
|---|---|
| **Windows 10 / 11** | LINE 那條路是 Win32 API，只有 Windows 有。只用 Facebook 的話其他系統也可以 |
| **Python 3.11 以上** | [python.org](https://www.python.org/downloads/) 下載，安裝時**勾選 Add Python to PATH** |
| **Google Chrome** | 用你電腦上已經裝的那個。程式會另外開一顆獨立的、專屬這支程式的 Chrome |
| **一個 Facebook 帳號** | 要發文的那個。程式不會幫你打密碼，登入是你自己在跳出來的視窗裡做 |
| **LINE 桌面版**（只有要發 LINE 才需要） | 要登入、而且**不能最小化**（被其他視窗蓋住沒關係） |

### 安裝

打開「命令提示字元」或 PowerShell，切到這個資料夾：

```bash
cd AI_post
python -m pip install -r requirements.txt
python -m playwright install chromium
```

第二行是裝 Playwright 的驅動程式（**不是**你要用的瀏覽器 —— 真正用的是你自己的 Chrome）。
這兩行只要跑一次。

### 啟動

```bash
python -m uvicorn app:app --port 8800
```

然後打開瀏覽器到 **http://127.0.0.1:8800**

視窗關掉程式就停了。要讓排程準時發文，**程式必須一直開著**。

> 排程過了時間超過 60 分鐘才發現程式沒開，那則會標成「錯過」而**不會補發**。
> 隔天早上隨機把昨天的內容發出去，比沒發更糟。

## 5. 第一次使用

### 5.1 設定 Facebook

1. 上方「Facebook 設定」→ **要發到哪裡**：

   | 填什麼 | 發到哪 |
   |---|---|
   | 留空 | 你自己的個人動態 |
   | `myshop` 或 `https://www.facebook.com/myshop` | 粉絲專頁 |
   | `https://www.facebook.com/groups/123456` | 社團 |

2. **給誰看**：只對個人動態有效。粉專一律公開、社團一律成員可見，程式會自動跳過這一關。

3. 按 **開啟專用瀏覽器** → 在跳出來的 Chrome 裡**自己登入** Facebook（含兩階段驗證）。
   登入完成後**把那個視窗關掉**。

> **那顆 Chrome 是獨立的**，不是你平常用的那個。登入狀態存在 `data/profiles/facebook/`，
> 之後就一直記得，不用每次登入。
>
> **它開著的時候會占住瀏覽器**，這時候有排程到了會顯示「排隊中」等它關掉 —— 這是故意的，
> 一顆 Chrome 設定檔不能同時被兩邊操作。

### 5.2 發第一篇

1. 把圖片丟進 `media/` 資料夾
2. 左邊寫**標題**（只有你看得到，用來認這則是什麼）和**內文**（真正會發出去的字）
3. 選圖、選時間、選「Facebook」
4. **第一次請先用「預演」** —— 它會把文字和圖片都放進發文框、停在按下發布之前、截圖給你看。
   不會真的發出去。
5. 確認沒問題再用「真的發」

### 5.3 看結果

任務列表照狀態分成四區：**進行中 / 已排程 / 已完成 / 沒發成功**。點任何一則可以看到
它要發的文字、圖片、時間，以及完成後的截圖。

狀態的意思：

| 狀態 | 意思 | 你要做什麼 |
|---|---|---|
| **已完成** | 在畫面上看到貼文了，有截圖 | 不用做什麼 |
| **不確定** | 發布鍵按下去了，但沒能確認 | **自己去 Facebook 看一眼**。系統不會自動重發 |
| **失敗** | 可以證明沒發出去 | 修好問題再跑一次是安全的，不會重複發文 |
| **錯過** | 時間到的時候程式沒開 | 重新排一個時間 |

> 為什麼「不確定」不自動重試？因為重複發文對你是真實傷害。寧可留一個要你去看的狀態，
> 也不要自作主張發第二次。

### 5.4 清除紀錄

每一區標題旁邊有**清除**按鈕，會刪掉那一區的紀錄。進行中和已排程的不會被刪掉。

## 6. LINE（選用）

LINE 沒有元件樹（詳見第 1、2 節），所以每個要點的東西都得先給它一張圖。

1. 開著 LINE（**別最小化**）→ 按「重新抓 LINE 畫面」
2. 在畫面上**框出**一個東西（例如「群組」分頁）→ 命名 → 存成模板
3. 把整條路徑都錄一遍：群組分頁 / 搜尋框 / 群組那一列 / 選單 / 記事本 / 建立貼文 /
   照片按鈕 / **發布** / **發完之後畫面上會出現的東西**
4. 填「目標群組名稱」，按「插入預設步驟骨架」改成你的流程，儲存

步驟詞彙（只有 7 個）：

| `do` | 作用 |
|---|---|
| `click_template` | 找到模板圖並點它 |
| `type` | 打字，`$body` / `$title` / `$group` 會被代換 |
| `press` | 按鍵（`enter` / `escape` / `backspace` / `tab`） |
| `wait` | 等 `seconds` 秒 |
| `attach_images` | 填 Windows 檔案視窗的路徑（上一步要先點開照片按鈕） |
| `fire_click_template` | **按下發布**。整份只能有一個，按下去就收不回來 |
| `verify_template` | 確認貼文真的出現 —— 這一步才產生證據 |

**存檔時會擋掉「不可能產生證據」的設定**：沒有 `fire`、有兩個 `fire`、或者 `fire` 之後
沒有 `verify` —— 最後那種無論跑得多順，結果永遠只會是「不確定」。

## 7. 交付給別人之前 ⚠️

**這個資料夾裡有你的 Facebook 登入狀態。**

```
data/profiles/     ← 你登入後的 Chrome 設定檔。拿到它的人可以用你的帳號發文
data/shots/        ← 執行時的截圖，裡面是你的 Facebook 畫面
data/ai_post.sqlite3  ← 貼文內容、執行紀錄、你填的網址
media/             ← 你放進去的圖片
```

原封不動把資料夾寄出去，等於把帳號一起寄出去。附了一支清乾淨的腳本：

```bash
python reset.py          # 會先列出要刪什麼，問你 y/n
```

它會清掉上面那四項，留下程式碼和設定結構。**在你要交付的那份複本上跑**，不要在自己這份跑
（會把你的登入狀態一起清掉）。

## 9. 已知限制

**Facebook**

- **小編用粉專身分發到社團時，會回報「不確定」。** 貼文**還是會發出去**，只是程式確認不到
  —— 它去查的是「登入的這個人在這個社團的貼文」那一頁，而用粉專身分發的文不在那裡。
  這一項還沒解決，詳見 `AGENTS.md` §6。
- **整篇都是 emoji 又沒有圖片的貼文確認不了** —— 沒有文字可找、沒有圖片 id 可比。
- Facebook 改版可能影響 agent 操作。agent 是看畫面做事不是寫死位置，所以改版通常只會變慢
  或失敗，不會發錯東西。

**LINE**

- 視窗**不能最小化**（被蓋住沒關係）
- LINE 改版 → 模板圖要重錄
- 上傳圖片時 Windows 檔案選擇視窗會搶焦點約一秒

**共通**

- 一次只跑一個發文（Chrome 設定檔獨佔鎖 + LINE 只有一個視窗），其他的排隊
- 時間是本機時間，沒有時區轉換
- 純圖沒文字的貼文存得進去，但排程時會被擋 —— 沒有文字就沒有東西可以當證據
